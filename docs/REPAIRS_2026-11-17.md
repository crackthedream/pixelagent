## Data compatibility

Existing project state is migrated on access to add a stable asset identity and a one-time legacy spending
baseline. Old financial logs are not rewritten. Already-lost historical attribution cannot be reconstructed
reliably and is not guessed.

Expression files created before provenance was recorded are preserved. They do not automatically become
trusted expressions for the current base sprite. The UI explains that a new set is needed; stale sets are kept
in the character folder and moved into expression history when a new source set is created. This repair does
not launch a paid regeneration.

Deletion and restoration are resumable transactions, not a claim that multiple directory moves happen
atomically. If an old orphan has no original project metadata, recovery uses a clearly named Recovered items
project. The owner still controls permanent deletion in the application.

Spending settings are described as admission thresholds over recorded charges, rather than exact provider
billing ceilings. Concurrent requests already in flight can settle above the threshold. Image pricing and
actual account credit entitlement still need independent account-level verification before financial claims.
